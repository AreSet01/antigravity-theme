## 一、执行摘要与总体健康度评分

### 1.1 总体评估
经过全量 CDP 自动化巡检与高刷 144Hz（6.94ms 帧预算）逐帧检测，Antigravity 2.x 的全量主题美化工程在**稳态浏览、主聊天流式阅读与文本上下滚动**方面表现极其优异，Median（P50）帧间隔稳定锁定在 **6.9ms ~ 7.0ms**，实现了原生级的 144Hz 极速响应。

然而，在**复合交互场景（侧边栏伸缩、设置面板挂载）**中，存在明显的**主线程长任务（Long Tasks 75ms ~ 288ms）**与**动效物理阻尼不统一、主题历史代码串扰**等典型问题。

## 三、六大核心动效场景深度诊断与根因分析

### 3.1 左右侧边栏展开与收起动效（Collapse / Expand）

- **现象**：
  - 用户在点击左侧栏折叠按钮时，均能观测到明显的顿挫感（视觉卡顿约 1~2 帧）。
  - 在 Phantom 主题中，展开侧栏时甚至有高达 **27.5% 的帧超过了 16.67ms**（跌破 60FPS），P95 达到 **48.6ms**。
- **深度代码根因**：
  1. **React 树状态颠簸**：当侧栏折叠/展开时，Antigravity 触发了内部 React 组件树的重排重绘，导致主线程出现了约 **75ms ~ 109ms 的同步 Long Task**。
  2. **根节点继承型 CSS 自定义属性失效灾难**：
     - 在原生 Antigravity 中，根节点 `.h-screen.w-screen` 上挂载了：
       `transition: --aux-pane-width 500ms, --sidebar-width 500ms;`
     - 这两个变量是通过 `@property` 注册且 `inherits: true` 的继承型属性。在动画的每一帧中，整个 DOM 树（1384 个元素）的计算样式被全量强制失效（Style Recalculation）。
     - **重大发现**：`pixel.css` 在第 1171 行虽然正确加入了阻断规则：
       ```css
       .h-screen.w-screen.flex.flex-col.bg-background {
         transition-property: none !important;
       }
       ```
     - **但是 `doodle.css`、`matcha.css` 和 `phantom.css` 遗漏了此优化**！导致这三套主题在每次侧栏滑动时遭受沉重的每帧重排惩罚。

### 3.2 全局确认与设置弹窗（Modal / Dialog）

- **现象**：
  - 点击“设置”按钮时，弹窗不是“平滑弹出”，而是“卡死约 1/4 秒后突然瞬跳显现”；而在按 Escape 退出弹窗时，却能以满帧 6.9ms 迅速消失。
  - 数据印证：打开弹窗时，主线程记录到了高达 **241ms ~ 288ms** 的超长 Long Task，最大尖峰达到 **298.6ms**，144Hz 掉帧率达到 **80% ~ 100%**。
- **深度代码根因**：
  1. **巨型子树同步挂载**：设置面板不是简单的几行文本，它包含“通用、应用、外观、模型、个性化定制、浏览器、项目”共 7 个功能区，包含所有模型列表、下拉选择器与本地路径设置。React 在用户点击的一瞬间**同步实例化并挂载全部 DOM**。
  2. **动画时间被计算阻塞完全淹没**：
     - 各主题中定义的弹窗入场动效仅有时长 150ms：
       - `matcha.css`: `animation: matcha-modal-pop-in 150ms cubic-bezier(0.16, 1, 0.3, 1)`
       - `phantom.css`: `animation: p5-modal-pop-in 150ms cubic-bezier(0.16, 1, 0.3, 1)`
       - `pixel.css`: `animation: pixel-modal-pop-in 150ms cubic-bezier(0.16, 1, 0.3, 1)`
     - 浏览器在执行完 260ms 的 JS 同步任务后，150ms 的 CSS 动画早已在主线程冻结中宣告结束，因此用户肉眼看到的不是动画过程，而是动画最后一帧的瞬态硬切。

### 3.3 模型选择框、下拉菜单与上下文菜单（Radix / Ariakit Popovers）

- **现象**：
  - 菜单类交互流畅度良好，平均帧时间在 **7.2ms ~ 8.1ms** 之间，Median（P50）完美落在 **6.9ms**。
  - 但在弹出模型选择器的一瞬间，存在一次 **57ms ~ 75ms 的 Long Task**。
- **深度代码根因**：
  - Radix UI / Floating UI 库在弹窗挂载时执行了 `computePosition()` 计算，进行边界碰撞检测与视口视差偏移计算。由于菜单体积小（仅 8 个模型项），整体掉帧率仅轻微扰动（144Hz 下 47%~50%，60Hz 下低于 4%）。

### 3.4 主聊天视窗上下滚动与流式输出动画（Scroll & Streaming）

- **现象**：
  - 在全长会话上下滑动中，四套主题的平均帧率均接近 144Hz 满刷极限（平均 7.57ms ~ 7.86ms，P50 6.9ms，60Hz 掉帧率极低：0.4% ~ 2.5%）。
  - 流式打字机光标（`px-streaming` / `doodle-caret`）在各主题下正常闪烁。
- **深度代码根因**：
  - 滚动容器受 GPU 合成加速（Compositor Thread），主线程无多余计算。
  - 偶发的 50ms~70ms 尖峰仅发生在视窗滚过 Markdown Monaco 代码块的虚拟化渲染边界时，属于合理的按需加载开销。

### 3.5 按钮与交互组件微动效（Hover, Active, Selected, Focus）

- **现象**：
  - 按钮在鼠标悬停时具有丰富的微动效：图标弹跳（`jiggle`）、发送箭头前顶（`nudge`）、复制完成标记（`check`）。
  - 但在不同主题中存在**动效物理阻尼不匹配**与**代码侵入式污染**问题。
- **深度代码根因**：
  - 在 `phantom.css` 与 `matcha.css` 中，按钮过渡广泛引用了并未在该上下文规范定义的 `--doodle-ease-snap`。
  - `phantom` 的 P5 潮酷怪盗风理应具备高张力、强冲击的干脆切角与波普回弹，但实际却在沿用 Doodle 的漫画手绘回弹。

### 3.6 持续性背景动效与稳态功耗（Spinner, Shimmer, Scanline, Pulse）

- **现象**：
  - 空闲状态下，1000ms 采样显示四套主题的 144Hz 帧时间均紧贴 7.1ms ~ 7.3ms，P50 为 6.9ms，未发生任何 Long Task（0 个）。
- **优点**：
  - `pixel.css` 明确规避了在全屏 CRT 扫描线上增加 `will-change`，从而避免了常驻 6MB 的全屏 GPU 合成显存开销。
  - 思考呼吸灯（`px-breathe`）采用了平滑的 1.6s 呼吸，相比旧版的二值硬闪更加柔和护眼。

## 四、四大主题视觉一致性与物理阻尼统一性评估

### 4.1 主题动效哲学与阻尼曲线对照矩阵

| 动效维度 | PIXEL (复古像素极客) | DOODLE (纯线稿漫画粉印) | MATCHA (治愈系抹茶日记) | PHANTOM (Persona 5 怪盗波普) |
|---|---|---|---|---|
| **核心美学哲学** | 8-Bit 街机硬边、CRT 扫描、阶梯步进 | 纯黑 G-Pen 墨水描边、漫画网点、粉印图章 | 和纸便签、治愈抹茶软绿、温润圆角手帐 | P5 红黑金高对比、怪盗预告信、波普斜切 |
| **推荐缓动曲线** | `steps(2)` / `steps(3)` / 整数格步进 | `cubic-bezier(0.18, 0.89, 0.32, 1.28)` (弹性回弹) | `cubic-bezier(0.25, 1, 0.5, 1)` (温润阻尼平滑衰减) | `cubic-bezier(0.05, 0.7, 0.1, 1.0)` / 锐利线性切割 |
| **现状缓动实现** | **弹窗误用平滑贝塞尔** `(0.16, 1, 0.3, 1)` | 完整实现了 `--doodle-ease-snap` 漫画弹跳 | **继承了 Doodle 的** `doodle-jiggle/nudge/snap` | **继承了 Doodle 的** `doodle-jiggle/nudge/snap` |
| **弹窗入场动效** | `pixel-modal-pop-in` (150ms 平滑) ❌ | `doodle-modal-pop-in` (150ms 漫画弹出) | `matcha-modal-pop-in` (150ms 和纸弹出) | `p5-modal-pop-in` (150ms 波普弹出) |
| **菜单入场动效** | `px-menu-enter 120ms steps(3)` ✔ | `doodle-menu-enter 120ms` ✔ | `matcha-menu-enter 120ms` ✔ | `p5-menu-enter 120ms` ✔ |
| **侧栏滚动/收起** | 平滑 500ms + 掐灭根 var (满刷) ✔ | 平滑 500ms + **未掐灭根 var (掉帧)** ❌ | 平滑 500ms + **未掐灭根 var (掉帧)** ❌ | 平滑 500ms + **未掐灭根 var (掉帧)** ❌ |

### 4.2 物理阻尼三大失调点诊断

1. **Pixel 主题的“平滑破功”**：
   - 菜单、按钮、滑块均严格遵守像素信仰使用 `steps(2)` 与 `steps(3)`。唯独全局弹窗 `pixel-modal-pop-in` 居然使用了连续平滑的 `cubic-bezier(0.16, 1, 0.3, 1)`，导致弹窗在缩放时产生亚像素模糊，违背了点阵位图的硬边像素规范。
2. **Matcha 抹茶主题的“性格错位”**：
   - 抹茶日记本应是优雅、舒缓、治愈的和纸质感。然而其按钮 hover、发送动画却继承了 `doodle-jiggle`（图标快速乱抖）与 `doodle-nudge`（箭头反复冲撞）。这种躁动的漫画感与抹茶的温润宁静产生严重违和。
3. **Phantom 怪盗主题的“张力不足”**：
   - P5 标志性的动效特征是极具进攻性的锐角倾斜（skew）、高反差几何切块与快速定格。现有的 `p5-modal-pop-in` 仅仅做了标准的垂直 translate + scale，缺乏 P5 标志性的红白斜切波普展开张力。

## 五、视觉巡检截图像素级缺陷清单

结合 `test-reports/screenshots/` 中的 24 张实机实测截图，发现以下具体缺陷：

### 缺陷 1：Tooltip 层叠上下文泄露穿透弹窗
- **佐证截图**：`doodle_06_settings_dialog.png` 与 `matcha_06_settings_dialog.png`
- **问题细节**：在打开“设置”对话框时，侧边栏左侧的“解析函数用法”悬浮卡片（`.react-tooltip`）依然顽固地浮现在设置弹窗的内容区上方，遮挡了“设置 > 通用”标签。
- **技术原因**：`.react-tooltip` 容器在样式表中被赋予了过高的层级，或者其 Portal 未在弹窗遮罩（Overlay）激活时被自动抑制。

### 缺陷 2：Matcha 与 Phantom 目录内遗留冗余垃圾文件
- **文件证据**：
  - `matcha-theme/doodle.css`（大小 85,207 字节）与 `matcha-theme/matcha.css` 完全并存。
  - `phantom-theme/doodle.css`（大小 102,284 字节）与 `phantom-theme/phantom.css` 完全并存。
- **风险**：虽然 `patch/pixelTheme.js` 优先匹配对应名称的 css，但在构建或者手动维护时极易误改到旧的 `doodle.css`，造成样式编辑无效或版本分裂。

### 缺陷 3：样式表头部版权与命名注记混乱
- **文件证据**：
  - `phantom.css` 第 8 行注记仍为：`DOODLE GRAVITY — Antigravity 2.x 纯线稿漫画手绘风主题`。
  - `matcha.css` 第 8 行注记仍为：`DOODLE GRAVITY — Antigravity 2.x 纯线稿漫画手绘风主题`。
- **影响**：破坏了主题工程规范度，容易误导后续维护者。

## 六、分阶段改进规划与代码级修复方案建议

> **说明**：本阶段为纯调查报告，严格不修改任何代码，以下方案供下一阶段改进参考。

### 阶段一：高刷性能补齐与掉帧消除（P0 紧急优化）
1. **为 Doodle / Matcha / Phantom 补齐根节点样式失效屏障**：
   在 `doodle.css`、`matcha.css`、`phantom.css` 中同步添加：
   ```css
   /* 阻断根节点继承型 CSS 自定义变量动画导致的 1384 节点全量样式重排 */
   .h-screen.w-screen.flex.flex-col.bg-background {
     transition-property: none !important;
   }
   [style*="36px - var(--aux-pane-width)"] {
     transition: padding-right 500ms var(--ease-expo-out, cubic-bezier(0.16, 1, 0.3, 1)) !important;
   }
   ```
2. **修复 Tooltip 穿透弹窗问题**：
   在全局或弹窗打开时给弹窗遮罩层设定标准层级，并压低已挂载的 Tooltip：
   ```css
   div.animate-modalFadeIn, [role="dialog"] {
     z-index: 2147483645 !important;
   }
   /* 当弹窗激活时，强制隐蔽页面上的残留 tooltip */
   body:has([role="dialog"]) [role="tooltip"],
   body:has([role="dialog"]) .react-tooltip {
     display: none !important;
     opacity: 0 !important;
     pointer-events: none !important;
   }
   ```

### 阶段二：物理阻尼与美学风格统一（P1 体验提升）
1. **Pixel 弹窗回归 8-Bit 点阵步进**：
   将 `pixel-modal-pop-in` 的缓动由 `cubic-bezier(0.16, 1, 0.3, 1)` 改为阶梯帧：
   ```css
   @keyframes pixel-modal-pop-in {
     0%   { opacity: 0; transform: scale(0.92); }
     50%  { opacity: 1; transform: scale(1.02); }
     100% { opacity: 1; transform: scale(1); }
   }
   html body [role="dialog"].animate-modalScaleIn {
     animation: pixel-modal-pop-in 140ms steps(3) forwards !important;
   }
   ```
2. **Matcha 抹茶重塑温润和纸阻尼**：
   剥离 Matcha 中的 `doodle-*` 命名，改为专属的和纸阻尼：
   ```css
   :root {
     --matcha-ease-paper: cubic-bezier(0.25, 1, 0.5, 1); /* 和纸温润缓落 */
   }
   ```
   移除跳动的 `jiggle`，改为柔和的呼吸阴影或细致的按压位移（0.5px）。
3. **Phantom 注入怪盗波普张力**：
   为弹窗增加 P5 标志性的红白斜切与锐利展开：
   ```css
   @keyframes p5-modal-pop-in {
     0%   { opacity: 0; transform: translate3d(0, 12px, 0) skewX(-2deg) scale(0.95); }
     70%  { opacity: 1; transform: translate3d(0, -2px, 0) skewX(1deg) scale(1.01); }
     100% { opacity: 1; transform: translate3d(0, 0, 0) skewX(0deg) scale(1); }
   }
   ```

### 阶段三：工程结构清洗与防退化体系（P2 长期维护）
1. 清理 `matcha-theme/doodle.css` 与 `phantom-theme/doodle.css` 冗余遗留文件。
2. 规范化各 CSS 文件头部注释与元数据命名。
3. 将本次测试脚本 `test-reports/benchmark_suite.js` 纳入 CI/本地提交流程，防止后续更新引入性能劣化。
