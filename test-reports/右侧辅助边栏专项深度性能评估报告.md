## 一、执行摘要与评估结论 (Executive Summary)

针对用户关于“**右侧的侧边栏有没有评估性能，先做**”的特别指示，我们通过专用 CDP 协议高精度自动化测试探针，对 Antigravity 客户端在四大主题（`pixel`、`phantom`、`doodle`、`matcha`）下的**右侧辅助侧边栏（Right Auxiliary Pane / 辅助工具抽屉）**展开与收起动作进行了首个专项、双向全周期深度评测。

### 1.1 核心评估结论

1. **历史评估缺漏补全**：此前系统级巡检仅对 `auxSidebarExpand`（展开）做了单向简易统计，**完全未对收起（Collapse）动效进行量化**，且未采集逐帧时间戳演化、全树 RecalcStyle 耗时与右上角工具栏过渡平滑度。本专项测试实现了**全周期双向实测闭环**。
2. **144Hz 高刷下收起性能优于展开**：收起动效（Collapse）的有效帧率明显高于展开（Expand）：
   - 收起阶段最高可达 **89.8 FPS**（`pixel`），P50 锁定在 **7.0ms**（贴合 144Hz 极速），P95 仅 **14.0ms**，60Hz 掉帧率低至 **4.8%**；
   - 展开阶段（Expand）因伴随右侧复杂 React 文档子树（Monaco/Markdown/Tab）的同步实例化与挂载，平均帧率为 **53.5 ~ 64.4 FPS**。
3. **主线程阻塞长任务（Long Tasks）恒定存在**：无论是展开还是收起，四大主题在触发瞬间均记录到了 **1 个 118ms ~ 148ms 的主线程长任务**（最大峰值位于 Doodle 收起的 **148ms** 与 Phantom 展开的 **138ms**），导致动画起始瞬间发生约 120ms~136ms 的首帧滞后尖峰（Max Spike）。
4. **根节点继承型 CSS 变量引发 RecalcStyle 账单差异**：
   - 原生 Antigravity 在根节点挂载了 `--aux-pane-width` 继承型变量（`inherits: true`）。
   - `pixel.css` 独家包含 `.h-screen.w-screen { transition-property: none !important; }` 阻断规则，其收起动效表现最稳（P95 达到创纪录的 **14.0ms**，60Hz 掉帧率仅 **4.8%**）；
   - `doodle`、`matcha`、`phantom` 未包含根变量阻断规则，其根节点 `transition-property: all` 使得动画过程中每帧均承受全树样式重算（RecalcStyle 39~58 次，累计耗时 167ms ~ 197ms）。
   - `doodle` 表现最为吃力，展开阶段 P50 跌至 **13.9ms**（跌破 144Hz 预算一倍），144Hz 掉帧率高达 **83.8%**，60Hz 掉帧率达 **35.1%**。
5. **右上角操作区 `padding-right: max(8px, 36px - var(--aux-pane-width))` 平滑度分析**：
   - 实测证明该容器自带 `transition: padding-right 500ms var(--ease-expo-out)`；
   - 展开时内边距从 **36.0px 平滑过渡到 8.0px**，收起时从 **8.0px 平滑回退到 36.0px**；
   - 视觉上不存在瞬间瞬跳硬切，但受 `cubic-bezier(0.16, 1, 0.3, 1)` 强初速指数衰减曲线影响，前 200ms 内已完成 85% 位移，叠加密集的 React 挂载长任务，会产生微弱的起始顿挫感。

## 三、右侧栏动画机制与关键属性深度剖析

### 3.1 根节点 `--aux-pane-width` 继承与全 DOM 树样式重算（Recalc Style）

在 Antigravity 架构中，右侧辅助面板的伸缩由根节点上的 CSS 变量控制：
- 根容器：`<div class="h-screen w-screen flex flex-col bg-background text-foreground ...">`
- 挂载属性：`--sidebar-width: 256px; --aux-pane-width: 0px;`（折叠） $\leftrightarrow$ `--aux-pane-width: calc((100vw - var(--sidebar-width)) * 0.37697227668249833);`（展开，约 490.7px）

#### 机制缺陷分析
1. **`@property` 注册与 `inherits: true` 的放大效应**：
   原生应用在运行时注册了继承型自定义属性。当根节点直接对自定义属性添加过渡（`transition: --aux-pane-width 500ms`）时，动画每一帧中变量值的变化都会向下传递给全树所有 DOM 节点（当前界面实测超过 **2050 个 DOM 节点**）。
2. **各主题处理策略对比**：
   - **Pixel 主题**（已阻断）：
     `pixel.css` 第 1171 行显式声明：
     ```css
     .h-screen.w-screen.flex.flex-col.bg-background {
       transition-property: none !important;
     }
     ```
     这切断了根节点上对 `--aux-pane-width` 的持续逐帧过渡，使得变量值在点击时直接突变（0px $\rightarrow$ 491px），消除了中间每一帧全树 2050 个节点的级联 Style Recalculation。
   - **Phantom / Doodle / Matcha 主题**（未阻断）：
     这三套主题并未包含上述阻断规则，其根节点计算后的 `transitionProperty` 为 `all`。因此在动画期间发生了 39 ~ 58 次强制 RecalcStyle，累计占用主线程 **167ms ~ 197ms**。

---

### 3.2 右上角操作区 `padding-right: max(8px, 36px - var(--aux-pane-width))` 过渡与跳变分析

#### 1. DOM 结构与样式声明
右上角工具栏（包含“打开 IDE”、辅助面板切换按钮等）挂载于如下元素：
```html
<div class="flex items-center justify-end shrink-0" 
     style="transition: padding-right 500ms var(--ease-expo-out); 
            padding-right: max(8px, 36px - var(--aux-pane-width));">
```

#### 2. 数学逻辑与位移区间
- **折叠状态**：`--aux-pane-width = 0px`  
  $$\text{paddingRight} = \max(8\text{px}, 36\text{px} - 0\text{px}) = 36\text{px}$$
- **展开状态**：`--aux-pane-width \approx 490.7\text{px}`  
  $$\text{paddingRight} = \max(8\text{px}, 36\text{px} - 490.7\text{px}) = \max(8\text{px}, -454.7\text{px}) = 8\text{px}$$
- **总位移量**：从 **36px** 变至 **8px**（共 **28px** 的水平平移），目的是在面板展开时为右侧工具栏腾出空间，避免与 Windows 原生窗口控制按钮（最小化、最大化、关闭）产生视差重叠。

#### 3. 逐帧时序实测：是否发生“跳变/瞬切”？
通过 `window.__runAuxPaneBench` 逐帧采样追踪 `paddingRight` 的计算值：

| 时间戳 $t$ (ms) | 单帧间隔 $\Delta t$ (ms) | 面板宽度 `paneWidth` | 右上角内边距 `paddingRight` | 根变量 `auxVar` | 运动状态阶段 |
|:---:|:---:|:---:|:---:|:---:|:---|
| **0.0 ms** | 0.0 | 0.0 px | **36.0 px** | 0px | 初始收起稳态 |
| **11.1 ms** | 11.1 | 0.0 px | **36.0 px** | 491.035px | 触发点击，React 状态变更 |
| **341.6 ms** | 41.7 | 487.4 px | **8.2 px** | 491.035px | 经历 125ms 挂载长任务后滑过大半 |
| **452.7 ms** | 20.8 | 490.6 px | **8.0 px** | 491.035px | 接近终点，阻尼收敛 |
| **494.3 ms** | 6.8 | 490.6 px | **8.0 px** | 491.035px | 满刷 144Hz 抵达终点 |
| **650.0 ms** | 7.0 | 490.7 px | **8.0 px** | 491.035px | 展开完成稳态 |

**分析结论**：
1. **非瞬跳，具备连续平滑插值**：由于该节点自身内联带有 `transition: padding-right 500ms var(--ease-expo-out)`，即使根节点上的 `--aux-pane-width` 发生阶跃式变化，CSS 转换引擎也会在 `padding-right` 属性上执行平滑动画，因此**不会发生 36px 瞬间瞬跳到 8px 的硬切**。
2. **视觉顿挫的主因在于 Expo-Out 贝塞尔曲线特征**：
   - 缓动函数为 `cubic-bezier(0.16, 1, 0.3, 1)`（指数级快速衰减）；
   - 在动画前 180ms 内，位移完成了总量的 85%（从 36px 骤降至 11px）；
   - 恰好在此时主线程发生 120ms 左右的 React 子树挂载 Long Task，导致前 150ms 常常只渲染了 2~3 帧，用户感知上会觉得“猛烈一冲然后立刻急停”，而非匀速滑移。

## 五、问题定位与工程优化建议

### 5.1 核心瓶颈归因

1. **瓶颈 1：React 同步实例化子树（不可规避的主线程硬开销）**：
   - 现象：展开瞬间恒定存在 **120ms ~ 138ms** 的 Long Task；收起瞬间恒定存在 **118ms ~ 148ms** 的卸载/布局重整 Long Task。
   - 根因：右侧面板并非简单纯文本容器，它包含 Tab 导航、Monaco/Markdown 多视图解析引擎以及辅助工具链上下文。用户点击按钮的一瞬间，React 必须完成 DOM 树挂载，导致主线程瞬间冻结 1~2 帧。
2. **瓶颈 2：`doodle`、`matcha`、`phantom` 根节点变量未阻断（CSS 级可优化开销）**：
   - 现象：Doodle 展开时 144Hz 掉帧率达到 83.8%，Layout 耗时达 133ms；Matcha 与 Phantom 每轮动画承受 40~58 次全树 RecalcStyle。
   - 根因：三套主题遗漏了 `.h-screen.w-screen { transition-property: none !important; }` 优化规则。

### 5.2 推荐优化代码方案 (Actionable Fixes for Orchestrator)

在 `doodle-theme/doodle.css`、`matcha-theme/matcha.css`、`phantom-theme/phantom.css` 的侧栏动效区域补入与 `pixel.css` 对齐的阻断规则：

```css
/* ------------------------------------------------------------
   右侧辅助面板 / 左侧栏高刷流畅度阻断优化
   掐灭根节点继承型 @property 变量动画，消除全 DOM 树逐帧 RecalcStyle
   ------------------------------------------------------------ */
.h-screen.w-screen.flex.flex-col.bg-background {
  transition-property: none !important;
}

/* 确保右上角工具栏平滑移动并锁定缓动阻尼 */
[style*="36px - var(--aux-pane-width)"] {
  transition: padding-right 500ms var(--ease-expo-out, cubic-bezier(0.16, 1, 0.3, 1)) !important;
}
```

## 六、未决问题与后续探索优先级 (Remaining Questions & Gaps)

1. **右侧辅助栏内部复杂编辑器滚动性能**：
   - 当前测试聚焦于右侧面板的**展开与收起整体过渡性能**。面板完全展开后，若在右侧 Monaco / Markdown 编辑器内部进行长文本高速滚动，其滚动帧率与主聊天视窗是否存在交互串扰，尚待在长会话状态下进一步压测。
2. **多显示器混合刷新率（144Hz + 60Hz）视口迁移**：
   - 当 Antigravity 窗口在高刷主屏（144Hz）拖拽至 60Hz 副屏时，Electron 的 rAF 回调调度是否存在帧间隔抖动，有待多显示器环境回归验证。
3. **后续改进工作推荐优先级**：
   - **P0（最高优先级）**：将 `.h-screen.w-screen { transition-property: none !important; }` 规则合入 `doodle.css`、`matcha.css` 与 `phantom.css`，预期可直接使三套主题收起帧率提升至 **80~90 FPS**，P95 降至 15ms 左右。
   - **P1**：评估针对 Expo-Out 强初速曲线与 React 同步渲染延迟的微调空间，探讨是否可通过 `requestIdleCallback` 或微动效延迟启动缓和起始尖峰感。
